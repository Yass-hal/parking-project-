4. In ParkingGarage.cancel, remove the test method instanceof CashPayment so
that method.refund(amount) is always called, and run the program again. What
happens? Which principle does CashPayment break, and why is the instanceof test
not an acceptable fix?

    Without the instanceof CashPayment check, the code throws an UnsupportedOperationException
    because CashPayment does not support automatic refunding
    CashPayment breaks the Liskov Substitution Principle (LSP), as it is not safe to substitute
    some other PaymentMethod with CashPayment when refund is needed
    The instanceof check is not the proper solution, since adding any other non-refundable
    payment method would require us to change the ParkingGarage class once again


5. Try to write a test that checks the fee of a truck parked for 4 hours and its checkout,
without creating the file parking.log. Why is it impossible with the current design?

    The truck checkout cannot be tested without the creation of parking.log since
    ParkingGarage always creates the FileLogger.

    The checkout() function always uses logger.log() where the receipt is written to the file. We cannot mock the FileLogger
    since the dependency is hard-coded in the ParkingGarage class

    This breaks the Dependency Inversion Principle (DIP). The fix would be to define a Logger interface and inject the
    dependency using the constructor so that we can mock the logger
